# Supabase migration security contract

PromptGen application objects in the `public` schema are created through checked-in migrations, not the Dashboard. The `postgres` migration owner has deny-by-default privileges for future tables, sequences, and functions. A migration that adds an object must therefore declare the intended Data API surface in the same file.

## Public table template

```sql
CREATE TABLE public.example (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES auth.users(id)
);

ALTER TABLE public.example ENABLE ROW LEVEL SECURITY;

REVOKE ALL ON TABLE public.example FROM PUBLIC, anon, authenticated;
GRANT SELECT ON TABLE public.example TO authenticated;
GRANT ALL ON TABLE public.example TO service_role;

REVOKE ALL ON SEQUENCE public.example_id_seq FROM PUBLIC, anon, authenticated;
GRANT USAGE, SELECT ON SEQUENCE public.example_id_seq TO service_role;

CREATE POLICY "example: select own"
  ON public.example
  FOR SELECT
  TO authenticated
  USING ((SELECT auth.uid()) = user_id);
```

If authenticated clients must insert rows, grant only `INSERT`, add a matching `WITH CHECK` policy, and grant the identity sequence only if the client actually needs it. Server-only tables keep RLS enabled, have no client policy or grant, and grant only the required privileges to `service_role`.

## Public function template

```sql
CREATE FUNCTION public.example_action()
RETURNS void
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
BEGIN
  -- implementation
END;
$$;

REVOKE ALL ON FUNCTION public.example_action() FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.example_action() TO service_role;
```

Use `SECURITY INVOKER` unless elevated rights are required. A `SECURITY DEFINER` function must pin `search_path`, schema-qualify security-sensitive objects, validate ownership inside the function, and expose `EXECUTE` only to the minimum roles.

## Review checklist

- Table and view migrations include explicit `REVOKE`, least-privilege `GRANT`, RLS enablement, and every required policy.
- Function migrations include an explicit execution boundary; `SECURITY DEFINER` functions pin `search_path`.
- Identity or serial columns include an explicit sequence decision.
- Client roles never receive privileges because a platform default happened to grant them.
- The migration records anon/authenticated/service-role preflight queries and a rollback statement.
- App objects are not created from the Dashboard, whose `supabase_admin` owner has separate platform-managed defaults.
